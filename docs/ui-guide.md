# 화면 기준

이 문서는 RepoScope 화면의 UI 라이브러리, 글꼴, 색, 모양, 화면 유형별 배치를 정한다. 화면 목록과 이동 경로는 [화면 흐름](screen-flow.md)을 따른다.

## 1. 라이브러리

UI 라이브러리는 Mantine 하나만 쓴다. 다른 UI 라이브러리나 CSS 프레임워크를 함께 쓰지 않는다.

| 용도 | 패키지 | 규칙 |
|---|---|---|
| 기본 부품 | `@mantine/core`, `@mantine/hooks` | 테마는 한 파일에서 정의한다 |
| 날짜 입력 | `@mantine/dates`, `dayjs` | 한국어, 월요일 시작으로 설정한다 |
| 알림 | `@mantine/notifications` | 저장 완료 같은 짧은 메시지에만 쓴다 |
| 차트 | `@mantine/charts`, `recharts` | 차트가 있는 화면만 따로 불러온다 |
| Markdown 표시 | `react-markdown`, `remark-gfm`, `rehype-sanitize` | HTML은 항상 `rehype-sanitize`를 거쳐 표시한다 |
| 글꼴 | `pretendard` | 2장 참고 |
| 아이콘 | GitHub Octicons | 필요한 아이콘만 SVG 경로로 넣는다 |

패키지를 추가하면 [OSS 라이선스 점검표](oss-license-check.md)에 기록한다.

## 2. 글꼴

Pretendard를 함께 배포해 모든 기기에서 같은 글꼴로 보이게 한다. `pretendard` 패키지의 `dist/web/variable/pretendardvariable-dynamic-subset.css`를 불러온다.

```css
font-family: 'Pretendard Variable', Pretendard, 'Noto Sans KR', sans-serif;
```

| 용도 | 크기 | 굵기 |
|---|---|---|
| 화면 제목 | 28px | 700 |
| 영역 제목 | 20px | 700 |
| 소제목, 카드 제목 | 16~18px | 700 |
| 본문, 표 | 14px | 400 |
| 보조 설명 | 13px | 400 |
| 배지, 캡션 | 12px | 600 |

- 숫자를 세로로 비교하는 표와 요약 숫자는 `font-variant-numeric: tabular-nums`를 쓴다.
- 강조는 굵기와 크기로 한다. 문장 안의 한 단어만 색을 바꾸거나 기울이지 않는다.
- 영문 대문자로만 쓴 라벨을 제목 위에 붙이지 않는다.

## 3. 색

밝은 화면만 지원한다.

### 기본 색

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 기본 파랑 | `#2157b0` | 주요 버튼, 링크, 선택 표시, 개발 단계 |
| 본문 | `#1b2a41` | 제목, 본문 |
| 보조 글자 | `#5a6b82` | 설명, 표 머리글, 날짜 |
| 선 | `#d8dfe8` | 영역 테두리, 입력란 |
| 연한 선 | `#e8edf3` | 영역 안 구분선, 표 행 구분 |
| 바탕 | `#f3f5f8` | 화면 배경 |
| 면 | `#ffffff` | 영역, 카드, 상단바 |
| 신호 주황 | `#c97a06` | 검증 단계, 이번 주 활동 |
| 완료 초록 | `#1d7f55` | 완료 단계 |
| 위험 | `#b83f50` | 삭제·보관·제외 버튼, 오류 |

- 기본 파랑은 Mantine 테마의 `primaryColor`로 등록하고 6번 색으로 둔다. 누른 상태는 7번 색이다.
- 글자는 바탕과의 대비를 4.5:1 이상으로 한다. 신호 주황을 글자에 쓸 때는 `#a46304`를 쓴다.
- 색만으로 정보를 전달하지 않는다. 진행 단계와 활동 종류는 항상 글자를 함께 표시한다.

### 진행 단계

| 단계 | 색 |
|---|---|
| 기획 | 회색 |
| 개발 | 기본 파랑 |
| 검증 | 신호 주황 |
| 완료 | 완료 초록 |

### 활동 종류

| 종류 | 색 |
|---|---|
| 커밋 | 회색 |
| PR | 기본 파랑 |
| 이슈 | 신호 주황 |
| 리뷰 | 보라 |

차트와 배지에서 같은 색을 쓴다.

## 4. 모양

| 요소 | 둥글기 |
|---|---|
| 배지, 작은 표시 | 3px |
| 버튼, 입력란, 선택 상자 | 4px |
| 영역, 카드, 저장소 상자 | 6px |
| 프로필 사진 | 원 |

- 영역은 그림자 없이 1px 선으로 구분한다. 그림자는 대화상자, 펼침 메뉴처럼 화면 위에 뜨는 요소에만 쓴다.
- 꾸밈용 그라데이션을 쓰지 않는다.
- 여백은 4px 단위로 둔다. 자주 쓰는 값은 8, 12, 16, 20, 24, 32px이다.
- 움직임은 사용자의 동작에 대한 반응(펼침, 선택)에만 쓰고, `prefers-reduced-motion` 설정을 따른다.

## 5. 화면 틀

### 상단바

상단바는 연계 프로젝트(2026URP) 화면의 상단바와 같은 모양을 쓴다. 로고는 넣지 않고 서비스 이름 `RepoScope`만 표시한다.

| 항목 | 값 |
|---|---|
| 높이 | 최소 85px |
| 배경, 아래 선 | `#ffffff`, `#e0e9f3` |
| 메뉴 글자 | 12px, 700, `#60728b` |
| 선택된 메뉴 | 글자 `#245bbc`, 배경 `#eaf2ff`, 둥글기 8px |
| 사용자 표시 | `이름 · 직위`, 글자 `#285db8`, 배경 `#eaf2ff`, 둥근 배지 |
| 로그아웃 | 흰 배경, 테두리 `#d5e0ef`, 글자 `#295eae`, 높이 42px |

- 좁은 화면에서도 한 줄을 유지한다. 1080px 이하에서는 메뉴가 넘치면 가로로 밀어서 보고, 860px 이하에서는 사용자 표시를 숨긴다.
- 메뉴는 [화면 흐름](screen-flow.md) 3장을 따른다.

### 본문

- 최대 폭 1600px, 좌우 여백 32px이다. 700px 이하에서는 15px로 줄인다.
- 본문 왼쪽 끝을 상단바의 서비스 이름과 맞춘다.
- 키보드 초점은 2px `#2157b0` 외곽선으로 표시한다.

## 6. 화면 유형

### 목록

| 형태 | 쓰는 경우 | 예 |
|---|---|---|
| 카드 격자 | 사용자가 속한 몇 개의 항목에 들어가는 화면 | V-3 내 프로젝트 |
| 줄 목록과 왼쪽 필터 | 항목이 많아 검색과 필터로 찾는 화면 | V-15 전체 프로젝트 |
| 표 | 같은 속성을 비교하거나 정렬하는 데이터 | 전체 활동, V-9 팀원, V-16 사용자, V-17 운영자 |

- 화면 제목과 주요 버튼은 같은 줄에 두고, 버튼은 오른쪽에 둔다.
- 필터는 줄 목록이면 왼쪽 칸(폭 200px), 표면 표 위 한 줄에 둔다.
- 카드 격자는 칸 폭이 300px 이상이 되도록 자동으로 열 수를 정한다.
- 페이지 이동은 목록 아래 오른쪽, 전체 건수는 왼쪽에 둔다.

### 상세

프로젝트 안 화면(V-6~V-12)이 해당한다.

- 위에서부터 상위 화면 링크, 제목과 상태 배지, 팀 이름과 기간, 탭을 둔다. 진행 단계 표시는 제목 오른쪽에 둔다.
- 본문은 넓은 칸과 오른쪽 정보 칸(폭 360px)으로 나눈다. 정보 칸에는 이름-값 목록과 짧은 목록을 둔다.
- 권한이 없는 동작의 버튼은 표시하지 않는다.

### 입력

V-2 가입, V-4 프로젝트 등록, V-12 설정, V-13·V-14 운영자 로그인과 초기 설정이 해당한다.

- 폼은 한 영역 안에서 소제목으로 묶음을 나눈다. 묶음 사이는 연한 선으로 구분한다.
- 넓은 화면에서는 폼 오른쪽에 미리보기나 안내를 둔다. 폼과 오른쪽 칸의 비율은 7:5다.
- 버튼은 폼 맨 아래 오른쪽에 두고, 주요 버튼을 가장 오른쪽에 둔다.
- 버튼 이름은 결과를 말한다. 예: `프로젝트 등록`, `저장`. `확인`, `제출`은 쓰지 않는다.
- 선택지가 2~3개이고 설명이 필요하면 선택 상자 대신 설명이 붙은 라디오 묶음을 쓴다.

### 대시보드

프로젝트의 활동 통계 화면이 해당한다.

- 위에서부터 기간 선택, 요약 숫자 띠, 차트, 표와 최근 목록, 집계 안내 순서로 둔다.
- 요약 숫자는 숫자마다 카드를 나누지 않고 한 영역 안에서 세로선으로 나눈다.
- 차트 막대는 둥글리지 않고, 가로 눈금선만 둔다.
- 팀원별 값은 이름순으로 표시한다. 활동량 순으로 정렬하거나 순위를 매기지 않는다.

### 안내

V-1 시작, V-18 오류가 해당한다.

- 제목, 한두 문장의 설명, 다음 행동 버튼 하나를 둔다.

### 좁은 화면

900px 이하에서는 두 칸 배치를 한 칸으로 쌓는다. 오른쪽 칸은 본문 아래로 내려간다.

## 7. 공통 부품

### 진행 단계 표시

기획, 개발, 검증, 완료 네 칸의 막대다. 지난 단계는 흐린 파랑, 현재 단계는 3장의 단계 색, 남은 단계는 회색으로 칠하고 현재 단계 이름을 글자로 함께 표시한다.

### 주간 활동 막대

최근 16주의 주간 활동 수를 막대 16개로 표시한다.

- 막대 높이는 가장 많은 주를 기준으로 한다.
- 활동이 없는 주는 회색 2px 막대로 표시한다.
- 이번 주 막대만 신호 주황으로 칠한다.
- 아래에 `16주 전`, `이번 주`를 표시하고, 전체 건수를 화면 낭독기용 설명으로 넣는다.

### 저장소 상자

연결된 저장소를 상자로 표시한다.

| 저장소 | 모양 | 동작 |
|---|---|---|
| 공개 | 배경 `#1f2328`, 흰 글자, GitHub 아이콘, 바깥 링크 아이콘 | 누르면 GitHub 저장소를 새 탭으로 연다 |
| 비공개 | 배경 `#eef1f5`, 테두리, 자물쇠 아이콘 | 링크 없음 |

- `소유자/저장소명`을 한 줄로 표시한다. 공간이 모자라면 소유자를 먼저 줄이고, 그다음 저장소명 끝을 `…`로 줄인다.
- 줄여 표시해도 전체 이름을 `title`과 화면 낭독기용 설명으로 제공한다.

### 프로필 사진

GitHub 계정이 있는 사용자는 `https://avatars.githubusercontent.com/u/{github_id}?s=64`의 사진을 원형으로 표시한다. 사진이 없거나 불러오지 못하면 이름 글자로 대신한다.

### 배지

진행 단계, 활동 종류, 역할을 표시한다. 연한 배경에 같은 계열의 진한 글자를 쓴다. 공개 범위처럼 상태를 보조로 알리는 배지는 테두리만 있는 모양을 쓴다.

## 8. 공통 상태

[화면 흐름](screen-flow.md) 6장의 상태를 다음 부품으로 표시한다.

| 상태 | 표시 |
|---|---|
| 불러오는 중 | 화면 틀을 유지하고 내용 자리에 `Skeleton`을 둔다 |
| 빈 상태 | 영역 안에 한 문장 안내와 다음 행동 버튼을 둔다 |
| 권한 없음, 없는 주소 | V-18 안내 화면 |
| 서버 오류 | 영역 안에 원인 한 문장과 `다시 시도` 버튼을 둔다 |
| 입력 오류 | 해당 입력란 아래에 고칠 내용을 위험 색으로 표시한다 |
| 저장 성공 | 화면 아래쪽 알림을 3초 동안 표시한다 |
| 위험한 동작 | 확인 대화상자를 띄우고, 실행 버튼은 위험 색에 동작 이름을 쓴다. 예: `팀원 제외` |

안내와 오류 문구는 무엇이 일어났는지와 어떻게 하면 되는지를 쓴다. 사과 표현은 쓰지 않는다.
