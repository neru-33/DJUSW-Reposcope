# 기능 명세

RepoScope는 캡스톤디자인 프로젝트의 기본정보, 팀 구성, 진행 상태, 결과물을 관리하고, 연결된 GitHub 저장소의 개발 활동을 수집해 보여 주는 웹 서비스다. 이 문서는 제출 버전이 갖출 기능과 완료 조건을 정한다.

## 1. 범위

| 번호 | 기능 | 우선순위 |
|---|---|---|
| S-1 | Webhook 수신 | 필수 |
| S-2 | 이벤트 처리 | 필수 |
| S-3 | 과거 기록과 누락 복구 | 필수 |
| R-1 | 학생 로그인·가입 | 필수 |
| R-2 | 운영자 로그인 | 필수 |
| R-3 | 프로젝트 | 필수 |
| R-4 | 팀원 | 필수 |
| R-5 | 진행 상태 | 필수 |
| R-6 | 결과물 | 필수 |
| R-7 | 저장소 연결 | 필수 |
| R-8 | 활동 조회 | 필수 |
| R-9 | 통계 | 필수 |
| R-10 | 사용자 관리 | 필수 |
| R-11 | 학기 분류 | 여유 시 |
| R-12 | 수집 상태 | 여유 시 |
| R-13 | LLM 요약 | 여유 시 |

필수 기능은 아래 시연 흐름이 끝까지 동작하는 것을 기준으로 한다.

```text
프로젝트 등록 → 팀원 구성 → 저장소 연결 → 활동 수집·조회 → 결과물 등록
```

## 2. 사용자와 권한

| 직위 | 설명 | 로그인 |
|---|---|---|
| `SUPER_ADMIN` | 최고관리자 | ID, 비밀번호, OTP |
| `ADMIN` | 운영 담당자 | ID, 비밀번호, OTP |
| `PROFESSOR` | 교수 | ID, 비밀번호, OTP |
| `STUDENT` | 참여 학생 | GitHub |
| `GUEST` | 가입을 끝내지 않은 사용자 | GitHub |

프로젝트 안에서 학생의 역할은 팀장과 팀원으로 나눈다.

| 작업 | `SUPER_ADMIN`, `ADMIN` | `PROFESSOR` | 팀장 | 팀원 | 다른 팀 학생 |
|---|---|---|---|---|---|
| 프로젝트 조회 | 가능 | 가능 | 가능 | 가능 | 공개 프로젝트만 |
| 프로젝트 수정·보관 | 가능 | 불가 | 가능 | 불가 | 불가 |
| 팀원 관리 | 가능 | 불가 | 가능 | 불가 | 불가 |
| 진행 상태 변경 | 가능 | 불가 | 가능 | 불가 | 불가 |
| 결과물 등록 | 가능 | 불가 | 가능 | 가능 | 불가 |
| 저장소 연결·해제 | 가능 | 불가 | 가능 | 불가 | 불가 |
| 활동·통계 조회 | 가능 | 가능 | 가능 | 가능 | 공개 프로젝트만 |
| 팀원·결과물·저장소 탭 조회 | 가능 | 가능 | 가능 | 가능 | 불가 |

공개 프로젝트는 공개 범위가 `학생 모두`인 프로젝트다. 다른 팀 학생은 공개 프로젝트의 개요, 활동, 통계를 조회만 할 수 있다.

사용자 관리는 `SUPER_ADMIN`, `ADMIN`만 할 수 있다. 운영자 계정 관리는 `SUPER_ADMIN`만 할 수 있다.

## 3. 공통 규칙

- 로그인하지 않은 요청은 `401`로 응답한다.
- 권한이 없거나 가입을 끝내지 않은 요청은 `403`으로 응답한다. 화면 이동만으로 막지 않고 API에서도 검사한다.
- 쓰기 요청은 CSRF 토큰을 검사한다.
- 시각은 UTC로 저장하고 화면에는 한국 시간으로 표시한다.
- 운영자의 조회 외 작업은 감사 로그에 작업자, 대상, 시각을 남긴다.
- 코드, diff, 커밋 작성자 이메일, 커밋 본문, PR·이슈 본문, GitHub 토큰은 저장하지 않는다.
- 수집 기록은 평가가 아니라 참고자료로 제공한다. 화면에도 이 안내를 표시한다.

## 4. 수집 기능

### S-1 Webhook 수신

GitHub 이벤트를 받아 검증하고 처리 대기열에 넣는다.

- `POST /webhook`으로 받고, 원본 본문으로 `X-Hub-Signature-256`을 검증한다. 불일치는 `401`로 응답한다.
- 원본 payload를 S3에 저장한 뒤 SQS로 메시지를 보낸다. 둘 중 하나라도 실패하면 5xx로 응답한다.
- SQS 메시지에는 payload 대신 S3 키와 이벤트 정보만 담는다.
- 대상 이벤트는 `installation`, `installation_repositories`, `push`, `pull_request`, `pull_request_review`, `issues`다. 그 외 이벤트는 저장하지 않고 `200`으로 응답한다.
- 수신 함수는 DB에 접근하지 않는다.

**완료 조건**

- [ ] 서명이 틀린 요청은 저장되지 않고 `401`을 받는다.
- [ ] 대상 이벤트는 S3 원본과 SQS 메시지가 함께 생성된다.
- [ ] 대상이 아닌 이벤트는 저장되지 않고 `200`을 받는다.

### S-2 이벤트 처리

worker가 SQS 메시지를 읽어 DB에 저장한다.

- 같은 `X-GitHub-Delivery` 값은 한 번만 처리한다.
- 활동은 `(repo_id, kind, ref)`를 기준으로 upsert한다. 커밋은 SHA, PR·이슈는 번호, 리뷰는 리뷰 ID가 `ref`다.
- 늦게 도착한 이벤트가 최신 상태를 되돌리지 않는다. `merged`는 최종 상태다.
- 리뷰는 소속 PR 번호를 `parent_ref`에 저장한다. 상태는 소문자로 저장하고 `PENDING`은 저장하지 않는다.
- PR의 `merged_at`은 값이 없는 이벤트로 지우지 않는다.
- 5회 실패한 메시지는 DLQ로 보내고 알람을 발생시킨다.

**완료 조건**

- [ ] 같은 이벤트를 두 번 보내도 활동이 하나만 저장된다.
- [ ] `closed`가 `opened`보다 먼저 와도 최종 상태는 `closed`다.
- [ ] 처리 실패 메시지가 DLQ로 이동하고 알람이 울린다.

### S-3 과거 기록과 누락 복구

Webhook으로 받지 못한 활동을 GitHub API로 채운다.

- 저장소가 연결되면 과거 커밋, PR, 이슈, 리뷰를 가져온다.
- 주기적으로 연결된 저장소를 다시 읽어 누락된 활동을 복구한다.
- 두 작업은 큐를 거치지 않고 이벤트 처리와 같은 규칙으로 upsert한다.
- 저장소 전체 선택으로 설치한 경우에는 과거 기록을 가져오지 않는다.

**완료 조건**

- [ ] 연결 전에 있던 활동이 조회된다.
- [ ] worker를 멈춘 사이에 발생한 활동이 복구되고 중복이 없다.

## 5. 사용자 기능

### R-1 학생 로그인·가입

학생은 GitHub로 로그인하고 학번과 이름을 입력해야 서비스를 쓸 수 있다.

1. GitHub App 사용자 인증으로 로그인한다.
2. 처음 로그인한 사용자는 `GUEST`로 만들고 가입 화면으로 보낸다.
3. 학번, 이름, 학과를 입력하고 개인정보 수집·이용에 동의한다.
4. 가입이 끝나면 `STUDENT`가 된다.

| 항목 | 규칙 |
|---|---|
| 학번 | 필수, 숫자 6~12자리, 중복 불가 |
| 이름 | 필수 |
| 학과 | 선택 |
| 개인정보 동의 | 필수, 동의 시각 저장 |

- 동의 안내에는 소속 프로젝트가 학생 모두에게 공개되면 이름, GitHub 로그인 이름, 프로필 사진, 활동 기록이 다른 학생에게 보인다는 내용을 포함한다.
- 사용자는 변경될 수 있는 로그인 이름이 아니라 GitHub 숫자 ID로 식별한다.
- GitHub 사용자 토큰은 로그인 중에만 쓰고 저장하지 않는다.
- 로그인할 때 사용자가 접근할 수 있는 저장소 목록을 갱신한다.
- 세션은 8시간 유지한다.

**완료 조건**

- [ ] 가입을 끝내지 않은 사용자는 프로젝트 API에서 `403`을 받는다.
- [ ] 이미 등록된 학번은 저장되지 않고 안내 문구가 표시된다.
- [ ] GitHub 로그인 이름이 바뀌어도 같은 계정으로 로그인된다.
- [ ] 로그아웃하면 세션이 끝난다.

### R-2 운영자 로그인

운영자는 학생과 별도의 주소에서 ID, 비밀번호, OTP로 로그인한다.

1. 첫 `SUPER_ADMIN`은 초기 설정값으로 한 번만 만든다. 초기 비밀번호는 코드에 넣지 않는다.
2. `SUPER_ADMIN`이 운영자 계정을 만들고 임시 ID와 비밀번호를 전달한다.
3. 운영자는 첫 로그인에서 ID와 비밀번호를 바꾸고 OTP를 등록한다.
4. 이후 로그인은 비밀번호와 OTP를 모두 확인한다.

| 항목 | 규칙 |
|---|---|
| 계정 단계 | `PASSWORD_CHANGE`, `OTP_SETUP`, `OTP`, `ACTIVE` |
| 임시 계정 유효 기간 | 발급 후 72시간 |
| 설정 단계 권한 | 비밀번호 변경과 OTP 등록만 가능 |
| 세션 | 미사용 30분 또는 로그인 8시간 뒤 만료 |
| 로그인 실패 제한 | IP별 15분 동안 20회 |
| 비밀번호 | 해시로 저장 |
| OTP | TOTP, 비밀키는 세션과 다른 키로 암호화해 저장 |

`SUPER_ADMIN`은 운영자의 비밀번호와 OTP를 초기화하고 계정을 비활성화할 수 있다.

**완료 조건**

- [ ] 임시 계정으로는 설정 전 프로젝트 API를 호출할 수 없다.
- [ ] 만료된 임시 계정은 로그인할 수 없다.
- [ ] OTP가 틀리면 로그인되지 않는다.
- [ ] 로그인 실패 제한을 넘으면 그 IP의 시도가 차단된다.
- [ ] `SUPER_ADMIN`을 잃어버린 경우의 복구 절차가 운영 문서에 있다.

### R-3 프로젝트

학생 팀장이 프로젝트를 등록하고 관리한다.

| 항목 | 규칙 |
|---|---|
| 이름 | 필수, 1~100자 |
| 팀 이름 | 선택, 50자 이하 |
| 설명 | 선택, 500자 이하. 목록 카드의 소개로 표시 |
| 시작일, 종료일 | 선택, 종료일은 시작일 이후 |
| 공개 범위 | `팀원에게만`(기본) 또는 `학생 모두` |
| 진행 상태 | 등록 시 `기획` |

- 프로젝트를 등록한 학생은 팀장이 된다.
- 삭제 대신 보관한다. 보관한 프로젝트는 기본 목록에서 빠지고 읽기 전용이 된다.
- 학생은 자기가 속한 프로젝트와 공개 프로젝트를 본다. 공개 프로젝트는 둘러보기 화면에서 이름, 팀 이름, 설명으로 검색하고 진행 상태로 거른다.
- 공개 범위는 팀장과 운영자가 바꿀 수 있다. 보관한 프로젝트는 둘러보기에 표시하지 않는다.
- 개요에는 대표 저장소의 README를 GitHub에서 가져와 표시한다. 대표 저장소가 공개 저장소일 때만 표시하고, 비공개 저장소이거나 README가 없으면 설명을 표시한다.

**완료 조건**

- [ ] 학생이 프로젝트를 등록하면 팀장으로 표시된다.
- [ ] 다른 팀 학생이 `팀원에게만` 공개한 프로젝트를 조회하면 `403`을 받는다.
- [ ] 다른 팀 학생은 공개 프로젝트의 개요, 활동, 통계를 볼 수 있고 수정할 수 없다.
- [ ] 보관한 프로젝트는 수정할 수 없다.
- [ ] 공개 대표 저장소의 README가 개요에 표시된다.

### R-4 팀원

팀장이 초대 코드를 만들고, 학생이 코드를 입력해 참여한다.

- 초대 코드는 프로젝트별로 하나만 유효하고 7일 뒤 만료된다. 다시 만들면 이전 코드는 무효가 된다.
- 가입을 끝낸 학생만 참여할 수 있다.
- 팀장은 팀원의 역할을 바꾸거나 팀원을 제외할 수 있다.
- 프로젝트에는 팀장이 항상 한 명 이상 있어야 한다.
- 제외된 팀원의 활동 기록은 유지하되 프로젝트 조회 권한은 사라진다.

**완료 조건**

- [ ] 유효한 코드를 입력하면 팀원으로 추가된다.
- [ ] 만료되었거나 무효가 된 코드는 거부된다.
- [ ] 마지막 팀장은 제외하거나 팀원으로 바꿀 수 없다.

### R-5 진행 상태

프로젝트 단계를 관리하고 변경 이력을 남긴다.

- 상태는 `기획`, `개발`, `검증`, `완료`다.
- 이전 단계로 되돌릴 수 있다.
- 변경할 때 이전 상태, 새 상태, 변경자, 시각, 선택 메모를 저장한다.

**완료 조건**

- [ ] 상태를 바꾸면 이력이 추가된다.
- [ ] 팀원이 상태를 바꾸려 하면 `403`을 받는다.

### R-6 결과물

프로젝트 결과물을 링크로 관리한다. 파일은 업로드하지 않는다.

| 항목 | 규칙 |
|---|---|
| 종류 | `문서`, `발표자료`, `시연 영상`, `저장소`, `기타` |
| 제목 | 필수, 1~100자 |
| 링크 | 필수, `https` 주소 |

- 팀원은 결과물을 등록할 수 있다.
- 등록자, 팀장, 운영자는 결과물을 수정하거나 삭제할 수 있다.

**완료 조건**

- [ ] 팀원이 결과물을 등록하면 프로젝트 화면에 표시된다.
- [ ] `https`가 아닌 링크는 저장되지 않는다.
- [ ] 다른 팀원이 등록한 결과물은 팀장과 운영자만 수정할 수 있다.

### R-7 저장소 연결

팀장이 GitHub App이 설치된 저장소를 프로젝트에 연결한다.

- 화면에 GitHub App 설치 안내를 표시한다. 저장소 전체 선택 대신 팀 저장소만 선택하도록 안내한다.
- 팀장이 접근할 수 있는 저장소만 연결 후보로 표시한다.
- 프로젝트 하나에 저장소 여러 개를 연결할 수 있다. 저장소 하나는 프로젝트 하나에만 연결한다.
- 처음 연결한 저장소가 대표 저장소가 된다. 팀장은 연결된 저장소 중에서 대표 저장소를 바꿀 수 있다. 대표 저장소의 연결을 해제하면 남은 저장소 중 가장 먼저 연결한 저장소가 대표가 된다.
- 연결된 저장소의 상태를 `수집 중`, `과거 기록 가져오는 중`, `연결 해제됨`으로 표시한다.
- 프로젝트에서 연결을 해제하면 이후 활동을 프로젝트에 표시하지 않는다.
- GitHub에서 App이나 저장소 선택을 제거하면 수집을 멈춘다. 저장소 화면에 이 방법을 안내한다.

**완료 조건**

- [ ] 접근 권한이 없는 저장소는 연결할 수 없다.
- [ ] 다른 프로젝트에 연결된 저장소는 연결할 수 없다.
- [ ] 비공개 저장소도 연결과 수집이 동작한다.
- [ ] 연결 해제 후 발생한 활동이 프로젝트에 표시되지 않는다.
- [ ] GitHub에서 App을 제거하면 새 활동이 수집되지 않는다.

### R-8 활동 조회

프로젝트와 팀원의 활동을 목록으로 보여 준다. 활동 기록은 수정할 수 없다.

- 조회 대상은 커밋, PR, 이슈, 리뷰다.
- 기간, 종류, 작성자, 저장소로 필터링한다.
- 최신순으로 표시하고 한 페이지에 50건을 보여 준다.
- 각 항목에 GitHub 링크를 표시한다.
- GitHub 계정과 연결되지 않은 활동은 `미연결 작성자`로 표시한다.

**완료 조건**

- [ ] 필터를 조합해도 해당 프로젝트의 활동만 조회된다.
- [ ] 항목의 링크가 GitHub의 해당 활동으로 이동한다.
- [ ] 다른 팀 학생은 공개 프로젝트의 활동만 조회할 수 있다.

### R-9 통계

프로젝트 현황과 활동 추이를 보여 준다. 조회할 때 집계하며 별도 집계 테이블은 두지 않는다.

| 단계 | 내용 |
|---|---|
| 1단계 | 프로젝트별 커밋·PR·이슈 수, 열린 PR 수, 병합 PR 수, 마지막 활동일 |
| 2단계 | 주간 활동 추이, 팀원별 PR·리뷰·이슈·커밋 표 |

| 지표 | 기준 시각 |
|---|---|
| 커밋 | 커밋 시각 |
| PR, 이슈 | 생성 시각 |
| 병합 PR | `merged_at` |
| 리뷰 | 리뷰 제출 시각 |

- 주는 한국 시간 월요일에 시작한다. 활동이 없는 주는 0으로 표시한다.
- 활동의 기본 단위는 PR이다.
- 커밋 수는 모든 브랜치를 포함한다. Squash 병합을 쓰면 작업 커밋과 병합 커밋이 함께 집계된다는 안내를 표시한다.
- 기여도 점수, 팀원 순위, 변경 줄 수 비교는 제공하지 않는다.
- 프로젝트 목록 카드에는 최근 16주의 주간 활동 수(커밋, PR, 이슈, 리뷰 합계)를 표시한다.

**완료 조건**

- [ ] 프로젝트 화면에 1단계 숫자가 표시된다.
- [ ] 주간 추이와 팀원별 표가 활동 목록과 일치한다.
- [ ] 참고자료 안내와 커밋 집계 안내가 표시된다.

### R-10 사용자 관리

운영자가 사용자를 조회하고 잘못된 가입 정보를 바로잡는다.

- 이름, 학번, GitHub 로그인 이름으로 검색한다.
- 학번, 이름, 학과를 수정할 수 있다.
- 사용자를 비활성화하면 로그인이 막힌다.
- 수정과 비활성화는 감사 로그에 남긴다.

**완료 조건**

- [ ] 운영자가 학번을 수정하면 중복 검사를 거친다.
- [ ] 비활성화된 사용자는 로그인할 수 없고 기존 세션도 끝난다.
- [ ] 변경 내용이 감사 로그에 남는다.
